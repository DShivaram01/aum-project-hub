# Deploying to AWS

The app runs on **ECS Fargate** behind an **Application Load Balancer**, with **RDS PostgreSQL**,
secrets in **Secrets Manager**, and logs, alarms and a dashboard in **CloudWatch**.
Everything is defined in CloudFormation under `infra/aws/`.

```text
            Internet
               |
     Application Load Balancer  (port 80, optional 443)
               |  health check: /actuator/health
     ECS Fargate service (Spring Boot container, port 8080)
        |                     |                    |
  RDS PostgreSQL     Secrets Manager         CloudWatch Logs
  (private, only     (DB password,           (JSON logs, metric filter,
   from the app)      JWT secret)             alarms, dashboard)
```

| File | What it creates |
|------|-----------------|
| `infra/aws/bootstrap.yml` | ECR repository, GitHub OIDC provider, IAM role GitHub Actions uses to deploy |
| `infra/aws/app.yml` | Security groups, RDS, JWT secret, ALB, ECS cluster/service/task, log group, alarms, dashboard |

## Security choices

- RDS is not publicly accessible; its security group only allows the app's security group.
- The app's security group only allows the load balancer.
- The DB password is generated by RDS (`ManageMasterUserPassword`) and the JWT secret by Secrets Manager.
  ECS injects both as environment variables at startup; neither appears in the template, the image, or GitHub.
- GitHub Actions authenticates with OIDC, so there are no long-lived AWS keys in the repository.
  The deploy role can only be assumed from the `main` branch of this repository.
- Tasks get a public IP so they can pull from ECR without a NAT gateway (saves about $30/month),
  but the security group still blocks all inbound traffic except from the load balancer.

## One-time setup

Requirements: AWS CLI v2 logged in to your account, Docker, and a region (examples use `us-east-1`).

```bash
export AWS_REGION=us-east-1
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
```

### 1. Bootstrap: ECR repository and deploy role

```bash
aws cloudformation deploy \
  --stack-name aum-project-hub-bootstrap \
  --template-file infra/aws/bootstrap.yml \
  --capabilities CAPABILITY_NAMED_IAM
```

If the account already has a GitHub OIDC provider, add
`--parameter-overrides CreateGitHubOidcProvider=false ExistingGitHubOidcProviderArn=<its ARN>`.

### 2. Push the first image

The ECS service needs an image to start, so push one by hand the first time:

```bash
REPO=$ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/aum-project-hub
aws ecr get-login-password | docker login --username AWS --password-stdin $ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com
docker build --platform linux/amd64 -t $REPO:initial .
docker push $REPO:initial
```

### 3. Create the app stack

The default VPC is fine. Pick two of its subnets in different availability zones:

```bash
VPC_ID=$(aws ec2 describe-vpcs --filters Name=isDefault,Values=true --query 'Vpcs[0].VpcId' --output text)
SUBNETS=$(aws ec2 describe-subnets --filters Name=vpc-id,Values=$VPC_ID \
  --query 'Subnets[0:2].SubnetId' --output text | tr '\t' ',')

aws cloudformation deploy \
  --stack-name aum-project-hub \
  --template-file infra/aws/app.yml \
  --capabilities CAPABILITY_NAMED_IAM \
  --parameter-overrides \
      VpcId=$VPC_ID \
      SubnetIds=$SUBNETS \
      ImageUri=$REPO:initial \
      AlarmEmail=you@example.com
```

This takes about 10-15 minutes (RDS is the slow part). Then:

```bash
aws cloudformation describe-stacks --stack-name aum-project-hub \
  --query 'Stacks[0].Outputs' --output table
curl http://<AppUrl>/actuator/health
```

Confirm the SNS email if you set `AlarmEmail`.

### 4. Turn on automatic deploys

In GitHub: **Settings -> Secrets and variables -> Actions -> Variables**, add:

| Variable | Value |
|----------|-------|
| `AWS_DEPLOY_ROLE_ARN` | `DeployRoleArn` output of the bootstrap stack |
| `AWS_REGION` | e.g. `us-east-1` |

From then on, every push to `main` runs tests, the Docker smoke test, and the CloudFormation lint,
then builds the image, pushes it to ECR tagged with the commit SHA, registers a new task definition and
waits for ECS to finish a rolling deploy. The deployment circuit breaker rolls back automatically if the
new tasks fail their health checks.

> When you update `app.yml` later, pass the image that is currently running as `ImageUri`,
> otherwise CloudFormation will roll the service back to the image named in the parameter.

## Monitoring

**Dashboard** (`DashboardUrl` output): request count, 4xx/5xx, p50/p95/p99 latency from the load balancer,
ECS CPU/memory, RDS CPU/connections, application errors, and the 20 slowest API requests.

**Alarms** (sent to the SNS topic / your email):

| Alarm | Condition |
|-------|-----------|
| `Target5xxAlarm` | 5 or more 5xx responses in 5 minutes |
| `LatencyAlarm` | p95 response time above 1 second for 15 minutes |
| `UnhealthyHostAlarm` | a task failing health checks for 3 minutes |
| `AppErrorAlarm` | 5 or more ERROR log lines in 5 minutes |
| `DatabaseCpuAlarm` | RDS CPU above 80% for 10 minutes |

**Logs**: with the `aws` profile the app writes one JSON object per line. Every API request produces a line like

```json
{"log":{"level":"INFO"},"message":"PUT /api/join-requests/1 -> 200 (31 ms)",
 "requestId":"2d22b5d9-...","httpMethod":"PUT","path":"/api/join-requests/1","status":200,"durationMs":31}
```

Useful CloudWatch Logs Insights queries on `/ecs/aum-project-hub`:

```text
# Latency percentiles per endpoint
filter ispresent(durationMs)
| stats count() as requests, pct(durationMs, 50) as p50, pct(durationMs, 95) as p95, pct(durationMs, 99) as p99 by httpMethod, path
| sort p95 desc

# Server errors per 5 minutes
filter status >= 500
| stats count() as errors by bin(5m)

# Everything that happened during one request (id from the X-Request-Id response header)
filter requestId = "2d22b5d9-..."
```

## Cost (us-east-1, roughly)

| Resource | Monthly |
|----------|---------|
| ALB | ~$16 + traffic |
| Fargate, 1 task 0.5 vCPU / 1 GB | ~$18 |
| RDS db.t4g.micro + 20 GB gp3 | ~$14 (free tier eligible for 12 months on new accounts) |
| Public IPv4 addresses (ALB + task) | ~$11 |
| Secrets Manager, CloudWatch | ~$2 |

## Tearing down

```bash
aws cloudformation delete-stack --stack-name aum-project-hub
# RDS keeps a final snapshot; delete it in the RDS console if you do not need it.
aws cloudformation wait stack-delete-complete --stack-name aum-project-hub
aws cloudformation delete-stack --stack-name aum-project-hub-bootstrap   # also empties and removes the ECR repository
```
